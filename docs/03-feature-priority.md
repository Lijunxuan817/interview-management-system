# 功能优先级

## P0 — 第一版必须做（不做则项目不合格）

| 编号 | 功能 | 角色 | 说明 |
|------|------|------|------|
| F01 | 用户注册与登录 | 全体 | 邮箱 + 密码，区分 applicant / mo / admin |
| F02 | 个人档案 | 申请者 | 专业、年级、技能、电话等 |
| F03 | 上传 PDF 简历 | 申请者 | 仅 PDF，大小限制 |
| F04 | 岗位列表 | 申请者 | 仅显示 status=open 的岗位 |
| F05 | 投递岗位 | 申请者 | 同一岗位不可重复投递 |
| F06 | 我的申请 / 进度 | 申请者 | pending / accepted / rejected |
| F07 | 发布岗位 | 课程组织者 | 标题、课程、类型、要求、人数 |
| F08 | 查看申请列表 | 课程组织者 | 某岗位下所有申请者 |
| F09 | 通过 / 拒绝申请 | 课程组织者 | 更新申请状态 |
| F10 | 助教负荷总览 | 系统管理员 | 统计已通过岗位数与列表 |
| F11 | 投递 Redis 分布式锁 | 系统 | POST /api/applications 加锁 lock:apply:{positionId}:{applicantId}；Day 12 写锁代码，Day 15 浏览器连点验证 |

## P1 — 有时间再做

- 邮件或站内消息通知（申请结果、新岗位）
- 岗位类型扩展：监考、答疑、实验批改等细分
- 导出申请列表为 Excel

## P2 — 可选（主流程完成后再做）

- **人工智能技能匹配（大模型）**：课程组织者查看申请时，大模型对比岗位要求与申请者技能（导师发补丁，学生只填密钥）
- 规则版技能匹配分（无 API Key 时用逗号标签算百分比）
- 识别申请者缺失的技能项
- 助教工作负荷过高警告（规则：已通过 ≥ N 个岗）
